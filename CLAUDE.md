# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Modular RC (https://rc.igorware.com/): a Bluetooth remote-controller PWA for RC cars. It is a single page that talks to the car over the **Web Bluetooth API** (Chromium browsers, Bluetooth Low Energy only, no Classic Bluetooth). There is no framework and no bundler. The browser loads `src/` as is, as native ES modules, served by Apache + PHP.

## Commands

- `npm test` runs the unit tests (`node --test "tests/**/*.test.js"`, Node's built-in runner, no extra dependencies)
- `node --test tests/status.test.js` runs one test file

Run Grunt through npx:

- `npx grunt` runs the default task: `jsonlint`, `eslint`, `htmllint`, `uglify`, `notify:done`
- `npx grunt eslint` lints `Gruntfile.cjs`, `src/assets/js/**/*.js` and `tests/**/*.js`
- `npx grunt jsonlint eslint` runs the lint checks only, without minifying
- `npx eslint src/assets/js/ui.js` lints a single file
- `npx grunt min` runs uglify only
- `npx grunt watch` re-lints `Gruntfile.cjs` and `src/assets/js/**/*.js` when they change

GitHub Actions (`.github/workflows/test.yml`) runs `npm ci` and `npm test` on Node 24 for pushes to `main` and for pull requests. CI does not lint.

Tests only cover the DOM-free logic (manifest download / CRC / cache / validation / grid layout / status decoding, version parsing, direction combining, command encoding, the command queue, the keepalive timer, display formatting). Anything touching Bluetooth or the page still needs Chrome with the car, or the in-app terminal screen to see sent and received traffic. The connect flow logs each step (`Connected to GATT server`, `Found primary service`, `Found characteristic`, ...), so the last line shows where a failed connection stopped.

The app modules do not lint clean: ESLint reports 7 errors that were already there before the module split, all from the WIP code listed at the bottom (unindented temporary/debug lines, the `nipplejs` global for the commented-out joystick). Compare error counts before and after a change instead of expecting a clean run. `tests/` lints clean.

Gotchas in the Grunt config:
- `uglify` minifies every `.js` in `src/assets/js` (except `*.min.js`), writing `*.min.js` next to them. A minified build is planned for later: `index.php` still loads the unminified files, and the minified modules import their siblings by unminified name, so switching needs the import map to point at the `.min.js` files. `eslint` skips `*.min.js`.
- `htmllint` only targets `**/*.html`. The only page is `index.php`, so htmllint effectively checks nothing.
- The `DEP0187 fs.existsSync` deprecation warning comes from grunt-cli's `liftup` dependency, not from this project, and can be ignored.

Toolchain choices ported from `P:\+projects\extensions\common`. Do not "fix" these by reinstalling the old packages:
- `grunt-eslint` is gone. `Gruntfile.cjs` registers its own `eslint` multitask against the ESLint Node API, because grunt-eslint pins ESLint 9 and would put a second ESLint into `node_modules`. ESLint 10 itself comes in as a peer dependency of `@eslint/js`.
- `eslint-plugin-brace-rules` is gone. It is unmaintained and crashes on ESLint 10. Style rules now come from `@stylistic/eslint-plugin`.
- `package.json` sets `"type": "module"`, so the Gruntfile must stay `.cjs`. `eslint.config.mjs` gives `**/*.cjs` files Node globals and `commonjs` mode, the app files in `src/assets/js` `sourceType: "module"` (except `service-worker.js`, a classic script), and `tests/` Node globals.

## Code style (enforced by eslint.config.mjs / .editorconfig)

- 4 spaces for indentation (2 for `.json`, `.yml` and `.md`, per `.editorconfig`), LF line endings, semicolons, ES2022. App files are ES modules, so no `'use strict'` (ESLint's `strict` rule rejects it in modules). `service-worker.js` and `Gruntfile.cjs` are scripts and keep `'use strict'`.
- **Allman braces for function declarations**: the opening `{` goes on its own line. Other blocks keep `{` on the same line. ESLint **no longer enforces this** (see the TODO in `eslint.config.mjs`), so match the surrounding code by hand.
- `space-before-function-paren`: `function ()` for anonymous functions, `function name()` for named ones.
- `object-curly-spacing: never` (`{a: 1}`), `eqeqeq`, `curly`, and one variable per line in declarations.
- **JSDoc is required** on functions: a description, `@param` with types, and `@returns`. Enum-like constants use `@typedef` plus `@readonly @enum`.
- `no-console` only allows `log` and `error`. Existing code calls `window.console.error`.

## Architecture

- `src/index.php` is the whole UI. Its only PHP job is cache busting: it embeds `filemtime()` into asset URLs (`/assets/css/app-YYYYmmddHHMMSS.css`), and `src/.htaccess` rewrites `name-<digits>(.min)?.js|css` back to the real file (JS is cached for a year). For the modules it prints an **import map** that sends every `assets/js/*.js` (except `service-worker.js` and `*.min.js`) from its plain URL to its timestamped URL, then loads `app.js` with `<script type="module">`. Modules import each other by plain relative path (`./bluetooth.js`) and the import map does the busting, so a new module needs no `index.php` change.
- `src/assets/js/` modules. **No module touches the DOM on import**: element lookups and event binding happen in init functions that `app.js` calls, so every module except `app.js` can be imported in Node tests. Keep it that way.
  - `constants.js`: enums (`SCREEN`, `CONNECTION_STATE`, `LOG_TYPE`, `DRIVE_STATE`), the legacy drive letters `COMMAND` (only the command queue's default merge groups), UUIDs, manifest constants and other numeric constants, typedefs.
  - `log.js`: the terminal log screen (`addLogEntry`) and `errorLogger`.
  - `manifest.js`: DOM-free car manifest logic (car-black#31): `crc32()`, `manifestHeaderParse()`, `manifestDownload()` (paging + CRC check + cache), `manifestCacheCreate()` (localStorage by CRC), `manifestValidate()`, `gridParse()`, `statusDecode()`, `speedLevels()` / `speedIndexFromPwm()`, `manifestDpads()`, `driveCommand()`, `manifestCommandGroups()`, and the `Manifest` / `ManifestCell` / `StatusDescriptor` / `GridLayout` typedefs.
  - `manifest-legacy.js`: `MANIFEST_LEGACY`, the built-in manifest (same schema) for firmware without `0xFFE5`, matching the controls and telemetry of firmware 1.3.x and older. It is also the layout shown before the first connect.
  - `status.js`: `versionParse()` only. Status and distance are decoded with the manifest.
  - `command-queue.js`: the send queue behind `bluetoothSendCommand()` (`commandQueueCreate()`), and the pure merge rules (`commandGroup()`, `commandQueueAdd()`). The drive and speed groups come from the manifest (`setGroups()`), with the legacy letters and digits as defaults.
  - `bluetooth.js`: connect / disconnect / reconnect, manifest loading, `bluetoothSendCommand()`, the characteristics. It never touches the page: it fires CustomEvents on `bluetoothEvents` (`state`, `device`, `version`, `manifest`, `values`, `receive`, `disconnected`, `error`, documented at the top of the file).
  - `ui.js`: screens, status bar (device name, version, battery), the connect screen's controls help. It only shows what it is given. The `format*()` helpers and `controlsHelpItems()` are pure and tested.
  - `controls.js`: the controller. `controlsRender(manifest)` builds `<controller-grid id="controller">` from the manifest and binds the cells; `controlsSetValues()` shows the status values in them. Also the terminal custom command. Owns what the app sent (drive state per d-pad, speed, `sent` toggle state) and what the car reports (`values`). `directionFromPressed()` and the keepalive helpers are pure and tested.
  - `app.js`: entry point. Wires `bluetoothEvents` to `ui` / `controls`, merges the `values` events into `carValues`, defines `reset()` and `errorHandler()`, runs the init functions and `init()` (which renders the legacy manifest), registers the service worker.
  - **Screens**: the `data-active-screen` attribute on `<rc-app id="app">` (`main` / `connect` / `error` / `terminal`) controls which `<app-screen>` is visible through CSS. `screenShow()` redirects `main` to `connect` while `bluetoothIsConnected()` is false (no command characteristic).
  - **Connection state**: the `data-status` attribute on `#app` (`disconnected` / `connecting` / `connected`) is shown or hidden through `[data-if-status]` spans.
  - **BLE** (service `BT_SERVICE` = `0xFFE0`, HM-10 style serial layout): `bluetoothConnect()` picks a device filtered by that service, then connects, gets the service and command characteristic `0xFFE1`, loads the manifest, sets `bluetoothCharacteristic` and fires `state: connected` (`app.js` then shows `main`). The 10 s `promiseTimeout()` only wraps `gatt.connect()`, so time spent in the device picker does not count.
    - `startNotifications()` on `0xFFE1` only runs when `characteristic.properties.notify` is set, because it throws otherwise. The current car firmware leaves NOTIFY off on `0xFFE1`, so the log shows `Characteristic does not support notifications` and the incoming `KEY=value;` path gets no data. This is expected.
    - **Manifest**: characteristic `0xFFE5` (READ + WRITE, car-black#31, firmware 1.4.0+). The blob is an 8-byte header (`u8` schema 1, `u8` encoding 0 = raw JSON, `u16le` payload length, `u32le` CRC-32/ISO-HDLC of the payload) followed by the JSON. It is read in pages: page 0 is a plain read (the car resets the offset on connect), each next page is a `u16le` offset write followed by a read, until `8 + length` bytes. The CRC is the cache key: `localStorage` `rc-manifest-cache` keeps the 5 newest payloads, so a cached reconnect reads page 0 only. `bluetoothManifestLoad()` runs before `state: connected` and before the status / distance subscriptions (decoding needs it), fires `manifest` and sets the command queue groups. A missing `0xFFE5`, a CRC mismatch, an unknown schema or invalid JSON logs the error and uses `MANIFEST_LEGACY`. Validation warnings (skipped cells / status entries, grid problems) go to the terminal log as `Manifest: ...`.
    - **Schema v1** (full spec in car-black#31): `car` (`id`, `name`, `fw`, `watchdog` `{drive, horn}` ms), `status[]` (`id`, `src` `ffe2`/`ffe3`, `at`, `t` `u8`/`u16le`/`bit` + `bit`, optional `max`, `none`, `unit`, `enum`), `grid` (rows of space-separated keys, `.` empty, a key repeated over a rectangle spans it, at most 12 × 12, landscape only), `cells` (key → `type` `button`/`hold`/`toggle`/`dpad`/`speed`/`display`/`color`, optional `id`, `label` (defaults to the key), `title`, `icon`, `danger`, `overrides`). Unknown types and incomplete cells are skipped (their area stays empty), a grid key without a cell stays empty, a cell not in the grid is not shown, and an invalid grid falls back to an automatic layout of the cells in key order (`MANIFEST_AUTO_COLUMNS` per row), never to a hard-coded one.
    - Front distance: characteristic `0xFFE2` (READ + NOTIFY), uint16 LE cm about every 200 ms, `400` (`none`) means nothing in range. Car status: characteristic `0xFFE3` (READ + NOTIFY, 7 bytes: drive state, motor PWM, selected speed (cruise PWM, stays the user's selection under Mad Max), flags bit0 autopilot / bit1-2 front/rear light / bit3 horn / bit4 obstacle stop / bit5 Mad Max, battery mV, battery %), on every change and every 2 s. Both are decoded with `statusDecode()` and the manifest's `status[]` into values by id (`drive`, `motor`, `cruise`, `autopilot`, `lightFront`, ..., `battery`, `batteryPct`, `distance`) and fired as `values` events; neither is written to the terminal log. Each subscription catches its own errors, so a car without them still connects.
    - The car's status is the truth for display, because the car changes state on its own (safety stop, disconnect failsafe, autopilot). The `drive` display, the speed picker (except within `SPEED_SYNC_HOLD` after the user moves it), toggle and hold pressed state (`aria-pressed`) all follow it. Battery is shown in the status bar.
    - Firmware version: characteristic `0xFFE4` (READ, ASCII, for example `1.1.0`) is shown after the device name in the status bar. Features are not gated on it: the manifest says what the car has.
    - After the manifest, the version, status and distance characteristics are read one after another, and each one is optional for older firmware.
    - Reconnect: the `gattserverdisconnected` listener is added only when a device is first picked. An unexpected disconnect clears the characteristics, fires `disconnected` (the app clears the car data) and calls `bluetoothConnect()` again with the same device. After a manual disconnect the app calls `reset()`. `controlsRender()` skips re-rendering an identical manifest, so a reconnect keeps the controller as it was.
    - `bluetoothSendCommand()` drops a command only when there is no characteristic. While a write is in flight, commands wait in the queue (`command-queue.js`), one GATT write at a time. A pending command of the same group is replaced by the newer one: drive letters of the manifest's d-pads (so the release stop replaces a pending drive and is never dropped), the speed keys, and payload commands per command letter. Other commands are not merged, and one already pending is not added twice. A disconnect or `bluetoothReset()` clears the queue. The third argument `log = false` keeps a command out of the terminal log, which the keepalive uses.
  - **Firmware**: the car side lives in `P:\+projects\arduino\car-black` (ESP32-C6). Its `bluetoothMapCommands()` in `command.ino` is the source of truth for command letters, its manifest template (`manifest.ino`, car-black#31) lists them for the RC, and its `const.h` holds the UUIDs. The firmware is not part of this repo.
  - **Controller** (`controls.js`, built from the manifest): `controlsRender()` sets `grid-template-columns` / `-rows` to `repeat(n, minmax(0, 1fr))` and each cell's `grid-area` from `gridParse()` (numbers only, never the car's strings). Cells get `.cell .cell-<type>`, `.cell-danger` for `danger`, and `title` / `aria-label` from `title`. In portrait the grid is hidden and `.rotate-hint` is shown (the installed PWA is locked to landscape). Cell types:
    - `dpad`: buttons by `axis` (`v` forward/back, `h` left/right, `both` a cross). Cells with the same `id` form one d-pad sharing `pressed` and a merged `cmd` map, so forward on the left plus right on the right gives `FR`. `directionFromPressed()` combines the buttons (forward wins over backward, left over right, nothing pressed gives `S`) and `driveCommand()` maps the state to its letter (a diagonal without one falls back to forward / backward).
    - `hold`: sends `press` on press, repeats it while held, and `release` once on release (the horn: `V` / `v`). If `release` is lost or missing, the car's watchdog ends it. Its pressed state shows the status with the same id (`horn`, which Mad Max also sets on its own).
    - `toggle`: sends `on` or `off`, chosen from its `status` value, or from the last sent state (`sent`) when the status is missing. An `overrides` toggle that is on dims its target (`.cell-overridden`), and a speed target shows `MAX` (Mad Max overrides `speed`; the slider still works and the car uses the selection again once it is off).
    - `speed`: a slider over the `keys` levels sorted by PWM (legacy: `1`-`9`, `0` = 10), sending the key of the selected level. It follows the `cruise` status (`speedIndexFromPwm()`). A cell taller than wide gets a vertical slider.
    - `display`: one status value, formatted by `formatStatusValue()` (`max` → %, `none` → dash, `distance` → `400+ cm`, bits On / Off, enums by name). The `drive` display falls back to the last sent drive state.
    - `button` sends `cmd` on click; `color` sends `cmd=` + 3 RGB bytes and is only shown when the car lists it.
  - **Wire protocol** (ASCII): the app sends single-character commands, or `cmd=<bytes>;` when there is a payload (`encodeCommand()`). All letters come from the manifest; `MANIFEST_LEGACY` has the ones of firmware 1.3.x (drive S F I R J B H L G, speed `1`–`0`, autopilot `X`/`x`, lights `W`/`w`, horn `V`/`v`, obstacle stop `C`/`c`, Mad Max `M`/`m`). **Firmware without Mad Max treats `M` as an unknown command, which stops the car and turns autopilot off**, so the legacy manifest assumes firmware with Mad Max (one car, latest firmware). **Keepalive** (watchdog from car-black#32): while a direction is held, the d-pad resends its drive letter every `car.watchdog.drive` / `KEEPALIVE_RESENDS` (166 ms for 500 ms; skipped while the `autopilot` toggle is on), and a held `hold` button resends `press` every `car.watchdog.horn` / 3 (333 ms). The timeouts default to `WATCHDOG_DRIVE_TIMEOUT` / `WATCHDOG_HORN_TIMEOUT`. Repeats are not logged. The hold buttons capture the pointer, so sliding off still releases them (the release handlers may run twice and must stay idempotent). `controlsReleaseAll()` releases the d-pads and holds on window `blur`, when the page is hidden, on disconnect and before a re-render, so a held button must be pressed again after a reconnect. On disconnect the `autopilot` toggle's sent state is reset (the firmware failsafe turns it off). Incoming data on `0xFFE1` is logged and parsed as `KEY=value;` pairs into `displayFields` in `ui.js`, which is currently empty, so no keys fill a display.
- `src/assets/js/service-worker.js` uses a network-first strategy with a cache fallback. `.htaccess` sets `Service-Worker-Allowed: /` so the worker can control the whole site.
- `src/assets/vendor/` contains third-party libraries (nipplejs). It is currently **unused**: its script tag and the joystick code are commented out. Do not edit it. The controller grid is plain CSS Grid; gridstack was removed (rc#11) because a drag-and-resize editor does not fit a fixed layout the car defines.
